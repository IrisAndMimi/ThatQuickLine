# 那個 QuickLine

鍵盤驅動的小工具台 —— 日期格式化、剪貼簿小物、連結轉換。
在聊天框打指令按 Enter，結果直接進剪貼簿。

**名稱分全名與簡寫**，差別在「對方知不知道這是什麼」：

| 常數 | 值 | 用在哪 | 為什麼 |
|---|---|---|---|
| `APP_NAME` | `那個 QuickLine` | 分頁標題 | 一堆分頁裡要認得出來，講全名 |
| `APP_SHORT_NAME` | `QuickLine` | 下拉選單第一項 | 人已經在裡面了，簡寫就夠 |

分頁標題會跟著目前所在位置變化：

| 位置 | 分頁標題 |
|---|---|
| 主選單 | `那個 QuickLine` |
| 功能內 | `複製日期 · 那個 QuickLine` |

**改名字**：兩個常數都在 `custom_js/core.js` 最上面，`<title>` 與下拉選單第一項都由它們生成。
（本文件、`functionMap.xml` 的 `app` 屬性等純文字則需一併手動更新。）

## 一、檔案結構

```
index.html                        入口頁
functionMap.xml                   功能結構紀錄（會被程式自動比對）
styles.css                        樣式
│
├─ data/
│   └─ return_msg_storage.js      【資料層】共用字串模板
│
└─ custom_js/
    ├─ core.js                    【核心層】對話框機制，不認識任何功能
    └─ features.js                【功能層】所有功能，各自 registerFeature() 登記
```

由 8 支 js 收斂為 **3 支**。

> `js/`（jquery、qrcode）2026-08-17 已整個刪除：index.html 從沒 `<script>` 載入過，
> 全專案也沒有任何 `$(...)`／`jQuery`／`QRCode` 呼叫，純粹是沒用到的第三方檔案。

## 二、為什麼是這個結構

> 你原本「一功能一檔、要移除就不 include」的直覺是對的，那就是 plugin / registry 模式。
> 但舊版有個隱藏問題：**核心認識功能**。

舊版 `chat-functions.js` 裡寫死了：

```js
if (headerSelect === '複製日期')      return getFormatDateHtmlC(...);
else if (headerSelect === '連結轉換') return routeLinkConvert(...);
```

所以刪掉 `copy_Date.js`，`chat-functions.js` 就壞了 —— 移除從來不是「只要不 include」。
選單的 `<option>` 也寫死在 html，是第三個要同步的地方。

**現在反過來**：核心不認識任何功能，功能自己登記自己。

```js
registerFeature({
    key: '複製日期',        // 下拉選單會自動長出這個選項
    buttons: `...`,         // 功能按鈕區 HTML
    help: `...`,            // 說明書區塊 HTML
    onSubmit: (msg, state) => ..., // 送出訊息時怎麼處理
    onRender: () => ...            // 按鈕區重建後的初始化（可省略）
});
```

核心只做 `FEATURES[key].onSubmit(msg)`。因此：

| 動作 | 要改幾個地方 |
|---|---|
| 新增功能 | **1 個** — features.js 複製一個區塊改寫 |
| 移除功能 | **1 個** — 刪掉那個區塊（core.js、index.html 都不用動） |

`features.js` 內每個功能都用 `#region` 分節，從 `#region` 到 `#endregion`
就是一個完整可刪的單位：

```
//#region 功能：剪貼簿  ────────────────
   ... 內部函式 ...
   registerFeature({ key:'剪貼簿', ... });
//#endregion 功能：剪貼簿
```

`#region` 是通用慣例，VS Code 等編輯器可直接收合整塊。

## 三、functionMap.xml

它的**形狀就是專案的結構** —— 檔案包著功能，功能包著它用到的東西：

```
<file path="custom_js/features.js">          功能層
  └─ <function key="剪貼簿">                  ← 對應 features.js 裡一個 #region 區塊
       ├─ <uses file="custom_js/core.js" part="copyToClipboard">     它靠什麼活著
       ├─ <ui>      重複文字 / 次數 / 特殊字元單選            它長什麼樣
       ├─ <io>      輸入 → 輸出 範例                        它做什麼
       └─ <remove>  刪掉整個區塊即可                        怎麼移除
```

`連結轉換` 因為整併了三種，底下再多一層 `<subFunction>`（蝦皮 / Line / APP深連結），
各自帶自己的 `<detect>`、`<io>`、`<remove>`，所以要單獨拆掉其中一種也有跡可循。

看這份檔案 = 看懂哪個功能住在哪、靠什麼活著、刪掉會影響誰。

> 巢狀不影響檢查：`querySelectorAll('function')` 是後代搜尋，包幾層都找得到。

但純文件的清單一定會跟程式碼走鐘 —— 你三個月後刪了功能忘了改它，它就變成謊言。
所以 `core.js` 的 `checkFunctionMap()` 會在載入時自動比對：

| 情況 | console |
|---|---|
| 一致 | `[functionMap] ✓ 與 functionMap.xml 一致` |
| xml 有、程式沒有 | `[functionMap] ✗ xml 有紀錄但實際未載入：剪貼簿` |
| 程式有、xml 沒有 | `[functionMap] ✗ 實際已載入但 xml 未紀錄：新功能` |

**以 `file://` 雙擊直接開啟時**，瀏覽器 CORS 會擋下讀取 xml，此時只印出實際功能清單供人工核對。
功能本身完全不受影響 —— 這只是開發時的提醒，不是執行的必要條件。

> 也可以讓 xml 變成真正的設定檔（程式依它決定載入什麼），但那樣就一定要起本地 server 才能開，
> 不符合你雙擊開檔的用法，所以沒有採用。

## 四、全鍵盤操作（指令層）

聊天框本身就是指令列，可以完全不碰滑鼠。

| 在哪 | 打什麼 | 會怎樣 |
|---|---|---|
| 主選單 | `1` 或 `date` | 進入該功能（代號打前幾個字也行） |
| 主選單 | `1 1 t` | **一次到位**：功能(1) + 選項(1) + 參數(t)，略過「已進入」的畫面直接執行 |
| 功能內 | 直接打參數 | 執行，例如 `1231` |
| 功能內 | `3` 或 `p` | 切換選項（編號或代號，代號可打唯一前綴） |
| 功能內 | `p 1231` | **切換選項並直接執行**，一次到位 |
| 功能內 | 多行輸入 | **一律當成純參數**，不解析選項 |
| 任何地方 | 打 `x` | **返回** —— 有提問就取消提問，否則回主選單 |
| 任何地方 | `Esc` | 同上；輸入框有字時則先清空 |

返回有兩種方式：打 `x` 送出（**手機也能用,這是主要方式**）、或按 `Esc`（桌機順手）。
其他按鍵：`Tab` 補全指令（多候選則循環）、`Enter` 送出、`Shift+Enter` 換行。

頁面一載入就把游標放進輸入框，全鍵盤操作不必先點一下滑鼠。

**主選單的路徑指令**（`1 1 t`）：第一個 token 選功能，剩下的字串原封不動交給
「功能內」那套判斷（選項、代號、參數的解析完全共用同一份邏輯，不重寫一份）。
所以熟悉指令的人可以完全跳過「進入」畫面，一行打完：

| 打什麼 | 等於分開打 |
|---|---|
| `1 1 t` | 先 `1`（進複製日期）→ 再 `1 t`（切 `/` 格式並帶入今天） |
| `2 rep 哈 5` | 先 `2`（進剪貼簿）→ 再 `rep 哈 5`（切重複文字並帶入「哈」×5） |
| `4 1+2` | 先 `4`（進計算機，沒有選項）→ 再 `1+2`（直接算） |
| `1 1` | 先 `1` → 再 `1`（只切選項，不帶參數 —— 沒給參數就還是會留在「已切換選項」畫面） |

只有「路徑後面有沒有東西」這一件事決定要不要略過畫面：沒有 → 正常進入該功能
（跟單獨打 `1` 一樣）；有 → 直接把剩下的丟給功能內邏輯處理，該執行就執行、
該回問就回問，不特別待遇。

**網址帶參數，開啟就直接送出**：路徑指令做出來之後，就能接一個更外層的用法——
在網址後面加 `?q=`，開啟頁面時自動把值填進輸入框並送出，等同幫你按了 Enter：

```
index.html?q=1 1 t
```

開這個網址，等同一進頁面就打「1 1 t」送出——直接複製今天的 `/` 格式日期，
連手都不用動。適合做成瀏覽器書籤或捷徑。用掉的 `?q=` 事後會從網址列拿掉
（`history.replaceState`），重新整理不會再送一次。只在真正載入頁面時處理，
bfcache 還原（例如手機切回分頁）不會重複觸發。

**為什麼輸入框是多行的**：選項本質是單一 token、不可能跨行，所以「有換行」就是明確的
「這是資料，不是指令」信號。打 `n 5` 會被當成「選項 nl + 參數 5」，
但 `n` `Shift+Enter` `5` 就毫無歧義 —— 衝突是消失，不是被繞過。
順帶解決：蝦皮／Line 的分享文字本來就是多行，過去貼進單行輸入框會被壓扁。

**功能代號**（`registerFeature` 的 `cmd` 欄位）：

| 代號 | 功能 |
|---|---|
| `date` | 複製日期 |
| `clip` | 剪貼簿 |
| `link` | 連結轉換 |
| `calc` | 計算機 |

指令與代號一律用等寬字顯示（`styles.css` 的 `--mono` 變數）——
全站的 Comic Sans 小寫 `t` 是十字形，跟「十」容易看錯，代號用它會誤讀。

**選項代號**寫在產生 radio 的 `data-cmd` 屬性上，與畫面同一份來源，不會有對照表不同步的問題：

| 功能 | 選項代號 |
|---|---|
| 複製日期 | `s` `b` `p` `ma` `cust` |
| 剪貼簿 | `rep` `nl` `tab` `zw` `fw` |
| 連結轉換 | `auto` `sp` `line` `app` |

三個地方各司其職，不互相重複：

| 位置 | 講什麼 | 特性 |
|---|---|---|
| 對話框氣泡 | 進入功能時的完整選項表與例子 | 資訊量最大，但會被捲走 |
| 提示列 | 你在哪、該打什麼形狀的東西 | 常駐，必須短 |
| 即時預覽 | 這次送出會怎樣 | **唯一**解讀輸入內容的地方 |

提示列刻意不解讀輸入 —— 兩邊都解讀的話不只重複，還會因為各寫一套比對邏輯而互相矛盾。

`registerFeature` 也因此把用法拆成兩欄：`usage` 只留簽章（給提示列，必須短）、
`examples` 獨立（只在氣泡顯示）。

預覽會分辨**「還沒打完」與「打錯了」** —— 輸入到一半本來就不合法，
這時顯示灰色的「…」提示（例如「還差次數」），而不是紅色 ✗ 嚇人；
判斷準則是「再多打幾個字有沒有可能變成合法」。送出時仍會照樣擋下。

即時預覽分層顯示：切到哪個**選項** → 它**怎麼解讀**你的輸入（標籤顯示「進入」）
→ **得到**什麼（或失敗原因、或「會回問你」）。「進入」那層由功能透過 `onPreview`
的 `as` 欄位回報，所以 `t` 會顯示成今天的實際日期、連結轉換會講出自動辨識的結果。
標籤取名「進入」是為了跟主選單選到功能時的「進入」呼應——都代表「已經確定要走這條路了」。

「進入」不必等到輸入完整才給——只要輸入的**形狀**已經能唯一判斷出會走哪條路，
就該馬上講，不要拖到打完才揭曉。例如剪貼簿的選項裡只有「重複文字」吃參數，
所以只要打到 `onPreview`（不管單行沒對上選項代號、還是換行輸入），就一定是
在打重複文字，`as` 應該從第一個字就顯示「複製-重複文字」，而不是等次數填完
才出現——不然使用者會誤以為還沒選定，或懷疑自己打錯了選項。
功能只要提供 `onPreview()` 即可加入預覽；前提是該功能的「算結果」與「複製」已經分離
（`buildDateText()` / `parseRepeatInput()` / `buildLinkText()` 就是為此拆出來的純函式）。

**看不見的字元在預覽裡看得見**：剪貼簿的重複文字如果本身是空白、換行、Tab、
零寬空格之類看不見的字元（例如重複 80 個空格、或用零寬空格繞過某些驗證），
不管是聊天框的即時預覽還是上方欄位的 `#repeat-preview`，直接顯示這些字元跟
沒打字沒兩樣，沒辦法確認對不對。`visualizeForPreview()` 用 Unicode 字元分類
（`\p{Zs}` 空格類、`\p{Cf}` 格式字元如零寬空格／BOM、`\p{Cc}` 控制字元）
一次涵蓋，不逐一列舉：Tab 顯示成 `⇥`、換行顯示成 `↵` 再保留真正的換行，
其餘全部（一般空格、全形空格、NBSP、零寬空格…）都用同一個 `·` 表示——
反正只是要讓你確認「這裡有東西」，不用分辨是哪一種。只影響**預覽怎麼顯示**，
複製到剪貼簿、最終結果氣泡裡的內容都還是原始文字，不會把 `·` 這個符號也複製進去。

多行輸入還有一個容易忽略的細節：`addMessage()` 一開始會把整段輸入 trim() 掉
頭尾空白，但如果要重複的文字剛好整行是空白、又剛好在輸入最前面（就是「80 個
空格」這個情境），trim() 會連中間的換行都吃掉，內容直接消失。所以 trim() 只用
在單行輸入；多行時整段照原樣使用，不再清理頭尾——多行本來就是刻意保留原樣
空白的通道。

功能若還缺東西會回問一句，你下一句話就是答案（`{ prompt, resume }` 機制，見 `state.pending`）；
此時按 `Esc` 是取消提問，不會離開功能。

輸入框上方有即時提示列，顯示候選指令或目前功能的用法與選項；
**功能一覽**（常看）由 core.js 開場時放進對話框；
**操作說明**（給不熟的人查）放在下方說明書區塊。

**指令表由 registry 自動生成** —— `registerFeature` 多帶 `cmd` 與 `usage` 兩個欄位即可，
core.js 完全不用改。選項編號與代號則直接從畫面上的第一組 radio 推導，連宣告都不必。

點選 UI 保留，且與指令**雙向同步**：打指令會設定下拉選單與單選鈕，用滑鼠點它們也照常生效。

## 七、歷史修正

**離線重新進入後，選單顯示與實際功能不一致**

原因：`updateActionButtons()` 原本只綁在 `<select onchange>`。但有兩種情況會還原選單的值卻不觸發 `change`：

1. **表單狀態還原** — 重新載入時瀏覽器自動把 `<select>` 還原成上次的值。
2. **bfcache** — 手機切分頁 / 離線再進入，頁面直接從快取還原，連 `DOMContentLoaded` 都不跑。

修正（`core.js`）：

```js
updateActionButtons();                                   // DOMContentLoaded 末端主動呼叫一次
window.addEventListener('pageshow', updateActionButtons); // bfcache 還原時同步
```
